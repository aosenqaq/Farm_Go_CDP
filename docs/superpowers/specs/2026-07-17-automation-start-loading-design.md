# 自动化启动加载反馈设计

## 目标

改善异步启动操作点击后的生硬感，让用户立即确认操作已受理，同时保持 Farm Go 现有按钮尺寸、配色和交互节奏。

用户已在视觉对比中选择方案 B：旋转加载图标加明确的进行中文案。

## 范围

本次统一三个异步入口：

- 农场自动化总开关处于停止状态时的“启动”操作。
- 注入提示弹窗的“启动小程序”操作。
- 注入提示弹窗的“重新启动”操作。

不修改自动化“停止”的视觉行为，不调整重新注入按钮，不改变任何后端调用、运行状态同步或消息提示逻辑。

## 交互设计

### 自动化启动

用户点击“启动”后，按钮立即进入忙碌状态：

- 电源图标替换为旋转的 `Loader2` 图标。
- 文案从“启动”替换为“启动中”。
- 按钮保持原有宽高和绿色主按钮样式。
- 按钮禁用，阻止重复提交。
- 增加 `aria-busy="true"`，向辅助技术表达异步状态。

请求成功后，现有运行状态更新负责将按钮切换为“停止”；请求失败时退出忙碌状态，并继续使用现有提示消息展示错误。

自动化停止请求继续使用当前的简单处理反馈，不套用本次启动动效。

### 注入提示弹窗

“启动小程序”和“重新启动”沿用各自已有的异步状态来源：

- `launching` 时显示旋转 `Loader2` 和“启动中”。
- `restarting` 时显示旋转 `Loader2` 和“重启中”。
- 忙碌时保持按钮尺寸稳定并禁用重复点击。
- 两个按钮使用与自动化启动按钮一致的忙碌样式标记和 `aria-busy` 语义。

弹窗现有图标、请求函数、禁用条件和错误处理不变。

## 实现方式

复用项目现有的 `primary-button`、`spin` 动画和 Lucide `Loader2` 图标，并增加一个轻量的统一忙碌类。三处按钮直接使用这一表现，不抽取新的通用按钮组件，避免为小范围变更增加组件层级。

全局 `spin` 动画继续作为唯一旋转实现。样式补充 `prefers-reduced-motion: reduce` 分支，在用户要求减少动态效果时停用连续旋转，同时仍保留加载图标和进行中文案，确保状态可辨识。

## 状态与错误处理

现有状态链路保持不变：

1. 点击处理函数设置对应的忙碌布尔值。
2. React 立即渲染加载图标、进行中文案、禁用状态和 `aria-busy`。
3. 异步请求完成或失败后，`finally` 清除忙碌状态。
4. 成功与失败继续走现有运行状态刷新和消息提示。

没有新增计时器、延迟或伪进度，加载反馈只覆盖真实异步操作时长。

## 测试与验收

组件测试应验证：

- 自动化启动请求未完成时显示“启动中”、旋转图标、禁用状态和 `aria-busy`。
- 同一忙碌阶段的重复点击不会再次触发启动请求。
- 自动化停止不使用“启动中”反馈。
- 注入弹窗在 `launching` 和 `restarting` 状态下分别显示正确文案、加载图标、禁用状态和 `aria-busy`。
- 非忙碌状态仍显示原有图标与文案。

完成后运行相关 Vitest 测试和前端生产构建，并在实际页面检查三个按钮在默认及减少动态效果设置下的布局稳定性。
