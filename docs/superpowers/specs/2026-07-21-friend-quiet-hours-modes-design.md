# 好友静默时间运行模式升级设计

## 目标

升级好友自动化中的静默时间功能，使其真正限制自动调度，并支持两种运行模式和可选作用范围：

- `指定时间休眠`：所选好友任务在时间窗口内不自动运行。
- `指定时间工作`：所选好友任务只在时间窗口内自动运行。
- 作用范围只包含 `偷菜`、`帮助`、`捣乱`，默认选择偷菜和帮助。

时间规则只限制自动调度。调度中心的手动执行始终允许。

## 现状

当前默认配置、前端表单和通用配置存储包含以下静默时间键：

- `autoFarmFriendQuietHoursEnabled`
- `autoFarmFriendQuietHoursStart`
- `autoFarmFriendQuietHoursEnd`

调度器和好友任务运行器没有读取这些键，因此当前静默时间配置可以保存，但不会阻止任何任务执行。现有界面还固定显示“指定时间内不进行偷菜/捣乱/帮助”，无法选择模式或范围。

## 配置模型

保留现有三个键，并新增：

- `autoFarmFriendQuietHoursMode`
  - `sleep`：指定时间休眠。
  - `work`：指定时间工作。
- `autoFarmFriendQuietHoursScopes`
  - 可包含 `steal`、`help`、`mischief`。

默认配置为：

```json
{
  "autoFarmFriendQuietHoursEnabled": false,
  "autoFarmFriendQuietHoursStart": "23:00",
  "autoFarmFriendQuietHoursEnd": "07:00",
  "autoFarmFriendQuietHoursMode": "sleep",
  "autoFarmFriendQuietHoursScopes": ["steal", "help"]
}
```

配置继续存放在现有账号级 `autoFarm.config` JSON 中，不新增数据库表或迁移。旧账号缺少新增键时由默认配置合并获得 `sleep` 与 `steal + help`。显式保存的空数组必须保留，表示当前规则不作用于任何好友任务。

读取规则时执行安全归一化：未知模式回退为 `sleep`，非法时间回退为相应默认值，未知作用范围被忽略，重复范围被去重。必须区分“键缺失”和“显式空数组”，避免把用户取消全部范围误改回默认范围。

## 时间语义

时间按运行 Farm_Go 的本机时区解释，窗口使用开始时间包含、结束时间不包含的半开区间。

- `08:00 → 18:00` 表示同日窗口。
- `23:00 → 07:00` 表示跨午夜窗口。
- 开始时间等于结束时间表示全天窗口。

休眠模式在窗口内阻止所选任务，工作模式在窗口外阻止所选任务。到达允许边界后，已经到期的任务立即恢复候选资格，不重置原有任务间隔。

## 调度器设计

在 `internal/farm/automation` 中增加一个纯时间规则单元。输入为配置、任务 ID 和当前时间，输出为：

- 当前任务是否允许自动运行。
- 若不允许，下一次允许运行的时间。

任务与范围映射为：

| 调度任务 | 作用范围 |
| --- | --- |
| `friend_steal` | `steal` |
| `friend_help` | `help` |
| `friend_mischief` | `mischief` |

非好友任务、未选中的好友任务、总开关关闭或显式空范围时始终允许。

调度器在以下三个位置复用同一判断：

1. `nextDueTaskLocked`：不允许的任务不进入候选队列，不启动运行器，不产生日志，也不增加失败次数。
2. `nextWakeDelay`：把任务的有效到期时间计算为原始到期时间与下一允许时间中的较晚者，避免受限任务到期后反复尝试。
3. `applyRuntimeToStateLocked`：受限时将任务状态中的 `NextRunAt` 展示为实际最早可运行时间；不修改底层原始间隔到期时间。

配置保存后，现有 `Scheduler.Configure` 负责唤醒调度循环并重新计算资格。规则只在派发前判断，不取消已开始执行的任务。

手动执行路径不调用这层自动资格筛选，因此保持不受时间规则限制。

## 界面设计

静默时间区域保留总开关，采用已确认的“分组两行”布局。

第一行包含：

- `启用静默时间` 总开关。
- `运行模式` 二段式选择：`指定时间休眠`、`指定时间工作`。
- `作用范围` 复选框：`偷菜`、`帮助`、`捣乱`。

第二行包含：

- `开始时间`。
- `结束时间`。

删除当前说明文字“指定时间内不进行偷菜/捣乱/帮助”。总开关关闭时，其余配置仍可编辑，以便先配置再启用。桌面端第一行三组、第二行两组；窄屏沿用现有响应式断点堆叠为单列。

界面继续使用现有好友设置区域的暖色、紧凑工具风格，只调整静默时间区域，不改动其他好友配置。

## 错误处理

- 非法配置由纯规则单元归一化，不让调度循环报错或产生周期性错误日志。
- 未识别任务不受限制。
- 空作用范围是合法配置，不显示错误，也不限制任务。
- 时间规则不会把被拦截识别为任务失败，不触发失败退避。

## 测试

Go 单元和调度器测试覆盖：

- 同日与跨午夜窗口。
- 两种运行模式。
- 开始、结束边界。
- 三个作用范围分别生效。
- 总开关关闭、空作用范围、未知及重复范围。
- 开始时间等于结束时间的全天语义。
- 非法时间和模式回退。
- 受限任务不进入候选队列，其他任务仍可运行。
- 到达允许边界后，已到期任务立即恢复。
- 状态中的 `NextRunAt` 为实际最早运行时间。
- 手动执行路径不受限制。

前端测试覆盖：

- 原说明文字不再渲染。
- 总开关、二段模式、三个范围和两个时间输入正确渲染。
- 默认范围为偷菜和帮助。
- 模式、范围和时间修改后写入现有 `config` 并保存。
- 响应式规则在窄屏堆叠，不产生横向溢出。

完成后运行完整 Go 测试、前端测试和前端构建，并确认发布目录引用新生成的静态资源。

## 非目标

- 不把时间规则扩展到好友互动之外的任务。
- 不限制调度中心手动执行。
- 不增加多时间段、按星期排程或节假日规则。
- 不中止已经运行中的好友任务。
