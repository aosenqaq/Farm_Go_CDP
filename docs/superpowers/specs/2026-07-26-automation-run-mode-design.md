# 自动化运行模式设计

## 目标

农场自动化提供按账号保存的两种运行模式：安全模式和仙人模式。运行模式只控制任务调度和好友互动的执行节奏，不覆盖或切换任务开关、优先级、间隔、仓库自动出售设置或其他默认配置。

原“应用推荐配置”入口和推荐配置套用能力由运行模式完全替换。

## 模式定义

### 默认与保存

- 模式合法值为 `safe` 和 `god`。
- 设置按账号保存到独立键 `autoFarm.runMode`，不放入任务配置 map。
- 首次创建且没有任何持久化自动农场记录的账号，使用 `safe`。首次进入自动化页时会写入该模式。
- 存在历史自动农场记录、但尚未保存运行模式的账号，迁移为 `god`，保证升级后的既有调度行为不改变。历史判定以该账号是否已保存任一自动农场设置键为准，不依赖会清理的运行日志。
- 已保存但值非法的模式按 `god` 归一化，避免配置损坏后意外降低既有账号的执行效率。
- 自动化状态向前端返回当前模式。切换成功后，后端返回已重配调度器的最新状态。

### 安全模式

- 同一账号的自动化任务同一时刻只能执行一个，包含仓库自动出售。
- 自动调度器按既有优先级选择到期任务，但一次只派发一个；前一个结束后才可派发下一个。
- 手动执行与自动任务共用任务锁。已有任务运行时，手动执行立即返回“当前有任务正在执行，请稍后再试”，不排队，也不与其并行。
- 已经开始的任务不被模式切换打断。每个任务开始时固定其模式快照；切换后未开始的新任务才使用新模式。
- 守护服务不参与任务锁，也不读取运行模式，继续独立运行。

### 仙人模式

- 维持当前调度器的资源并发规则、好友任务的现有并发和批量行为，以及用户已有的等待配置。
- 不额外插入安全模式的随机等待。

## 好友互动安全规则

安全模式下，好友黑白名单、护主犬筛选、每日限制、候选数量限制和作物规则的既有顺序不变。筛选完成后按候选列表顺序执行所有可操作好友。

### 偷菜

1. 逐个处理可偷好友；首个好友不等待，之后每位好友开始前随机等待 `100-1000ms`。
2. 对当前好友只进入和解析农场一次，得到所有可偷地块后用完整地块列表调用一次偷菜协议，与手动单好友入口保持相同的已验证协议形状。
3. 单个好友的偷菜请求失败时记录失败后继续处理下一位好友。

### 捣乱

1. 逐个处理可捣乱好友；首个好友不等待，之后每位好友开始前随机等待 `100-1000ms`。
2. 对当前好友一次取得可放草和可放虫地块。
3. 放草、放虫均拆为单地块协议调用；相邻地块操作之间随机等待 `100-200ms`。不能继续使用一次把同类多个地块合并发送的批量调用。
4. 单个地块失败时停止该好友剩余地块，记录失败后继续处理下一位好友。每日上限语义保持现有逻辑。

### 帮忙

1. 逐个处理可帮忙好友；首个好友不等待，之后每位好友开始前随机等待 `100-1000ms`。
2. 每个好友继续使用现有一键帮忙协议，不拆分该好友的地块，也不增加地块等待。
3. 单个好友失败后记录失败并继续处理下一位好友。

所有新增等待必须可由任务上下文取消。随机数和等待函数须通过运行时策略注入，以便测试固定等待值且不依赖真实时间。

## 后端设计

运行模式作为自动化设置的显式字段贯穿存储 DTO、自动化设置、自动化状态和 Wails 绑定。后端新增仅切换模式的授权接口：

```go
func (a *App) SetFarmAutomationRunMode(mode string) (automation.State, error)
```

调用顺序为：校验授权和模式值，加载当前账号设置，替换模式字段，持久化 `autoFarm.runMode`，成功后重配当前账号调度器并返回状态。存储失败时不更新内存调度器，也不返回成功状态。

调度器在安全模式下限制自动派发数量为一个。应用层维护与当前账号自动任务共享的执行锁，供调度器运行器和手动运行入口使用：自动任务获得锁后执行；手动入口只尝试获得锁，失败即返回忙碌结果。模式为仙人时不启用这个全局串行限制。

好友运行时接收任务开始时的模式快照。安全模式选择逐个好友和逐个地块路径；仙人模式保留现有实现路径，防止性能模式发生行为回退。

## 前端交互

农场自动化页头部删除“应用推荐配置”按钮，替换为紧凑控件：

```text
运行模式：仙人模式  [齿轮]
```

点击控件或齿轮打开“运行模式”弹窗。弹窗用两张卡片说明模式，不使用“串行、并发、资源调度”等技术术语：

- 安全模式：软件会慢一点做事，一件任务做完再做下一件；处理好友、地块和自动出售时，动作之间会停一停。
- 仙人模式：能一起做的任务会尽量同时做，完成速度更快；处理好友、地块和自动出售时，操作会更紧凑。

弹窗还明确说明：无论选择哪个模式，守护服务都会照常自己运行。

当前模式显示“已选”。用户选择当前模式时，“下一步”不可用。选择不同模式后进入二次确认弹窗，确认文案直接说明切换后的实际变化和守护服务不受影响。保存期间关闭、返回和确认按钮禁用；成功后关闭弹窗、刷新状态并给出简短成功提示；失败时保留所选项和弹窗，显示错误，页面当前模式不变。

## 移除内容

本次删除以下仅服务于推荐配置的实现：

- 自动化页的推荐配置按钮和确认弹窗。
- 前端 `onApplyRecommendedConfig` 传递链及其测试。
- Wails `ApplyRecommendedFarmAutomationConfig` 绑定。
- 后端推荐快照、应用推荐接口和推荐配置专用的自动农场/仓库原子保存接口及测试。

不删除常规自动农场设置保存和仓库自动出售保存路径。

## 错误处理

- 非法模式值返回校验错误，既不保存也不重配调度器。
- 存储读写失败返回错误，当前运行模式与调度器保持原状。
- 安全模式下手动运行撞到在执行任务时返回 `StatusRuntimeBusy`，不开始运行。
- 等待被取消、好友协议失败、每日限制与现有结果汇总格式保持兼容，并新增逐个好友/地块路径的正确统计。

## 测试

- 存储：账号隔离、全新账号默认安全模式、历史账号缺少模式时迁移仙人模式、非法值归一化为仙人模式、读写模式不影响任务和配置。
- 应用接口：授权、非法值、保存失败不生效、成功后仅更新模式并重配调度器。
- 调度器：仙人模式仍允许既有可并发任务；安全模式同一轮仅启动一个任务，包含仓库自动出售；切换不取消已运行任务，后续任务遵循新模式。
- 执行锁：安全模式下自动任务运行期间手动任务返回忙碌；守护服务不受锁影响。
- 好友运行时：安全模式偷菜、帮忙和捣乱的好友顺序、`100-1000ms` 好友等待、偷菜的完整地块列表请求、捣乱的 `100-200ms` 地块等待、单个好友失败后的继续策略、每日限制和汇总；仙人模式保留原有并发和批量调用。
- 前端：紧凑入口替换推荐配置入口、易懂模式文案、当前模式不可重复确认、两步确认、保存中状态、成功刷新、失败保留弹窗。
- 回归：Go 全量测试、前端测试、前端生产构建和空白检查。

## 非目标

- 本次不提供运行模式的任务模板或按模式重置任务默认配置。
- 本次不改变好友名单、作物名单、护主犬、静默时段、守护服务或仓库出售的业务规则。
- 本次不增加用户可编辑的安全模式等待范围。
