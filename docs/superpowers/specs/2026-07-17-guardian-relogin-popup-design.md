# 守护服务登录失败弹窗自动处理设计

## 目标

当 QQ 经典农场出现“平台登录失败，是否重新登录？”双按钮提示弹窗时，守护服务在下一次运行时检测中立即触发“重新登录”，不增加额外延时，也绝不触发“退出游戏”。

## 现状与根因

`resources/wmpf/button.js` 已包含“平台登录失败”“是否重新登录”“重新登录”等文字判断，并将这类提示纳入现有网络重连 watcher。但是当前弹窗发现逻辑只查找 `ServerKickOutUICom`，测试运行时也只模拟该组件。

截图中的提示采用通用双按钮弹窗结构。即使文字判断能够识别其内容，只要组件不是 `ServerKickOutUICom`，当前发现链路就得不到弹窗摘要和确认按钮，watcher 会把它视为不可见，因此不会自动处理。

## 范围

本次修改只扩展运行时弹窗发现与正向按钮点击能力，并复用现有网络重连 watcher、恢复等待、同一弹窗去重和 `network_reconnect` 事件上报。

不新增守护设置项，不改变检测间隔，不修改异地登录延时策略，不使用窗口坐标点击，也不以重启 QQ 进程代替弹窗处理。

## 识别设计

保留 `ServerKickOutUICom` 作为现有快速路径，并增加活动通用弹窗的受限扫描。候选必须同时满足：

- 弹窗正文包含“平台登录失败”或等价的“登录失败 / 是否重新登录”语义。
- 存在文本为“重新登录”的正向按钮。
- 若存在“退出游戏”按钮，它只能作为反向按钮记录，不能成为点击候选。

扫描只读取活动节点及其组件、标签和按钮事件，不根据屏幕坐标、颜色或子节点顺序推断正向按钮。不能唯一确定“重新登录”按钮时，将其视为未匹配并保持弹窗不动；只有已经唯一识别但点击 handler 无法调用时，才沿用现有失败事件记录。

## 点击与数据流

`getReconnectPromptState` 合并现有专用组件摘要和新的通用弹窗摘要，并继续使用 `isReloginPromptText` 判断登录失败提示。

`clickReconnectPrompt` 根据摘要携带的正向按钮节点执行点击：优先复用 `smartClick` 触发该节点已注册的 `cc.Button.clickEvents`；只有组件已经提供明确的确认 handler 时才使用组件回退。处理结果继续使用 `relogin_*` 的 `via` 值，便于守护事件区分处理路径。

现有 `startReconnectWatcher` 在下一次轮询发现该提示后立即调用点击逻辑。点击后继续等待弹窗消失和游戏恢复；同一可见弹窗若已得到成功或终止结果，不重复点击。

## 安全与错误处理

- 只有语义和正向按钮均匹配时才自动处理，避免误点普通确认弹窗。
- “退出游戏”节点永远不进入正向按钮候选。
- 弹窗结构不完整或按钮不唯一时不做猜测、不点击；唯一按钮没有可调用 handler 时返回 `reconnect_handler_not_found`。
- 点击后未恢复时沿用现有 `recover_timeout` 和单弹窗回合抑制机制，避免连续点击。

## 测试与验收

先在 `scripts/test-guardian-runtime-watchers.js` 增加失败回归用例，再实现生产代码。测试至少覆盖：

- 通用双按钮登录失败弹窗会且只会触发一次“重新登录”。
- “退出游戏”的 handler 调用次数始终为零。
- 点击结果标记为已处理，并记录 `relogin_*` 点击路径。
- 只有相似标题、缺少登录失败正文或缺少唯一“重新登录”按钮的弹窗不会被点击。
- 原有 `ServerKickOutUICom` 网络重连、恢复超时、同回合去重、异地登录和 watcher 停止测试继续通过。

完成后运行守护 watcher Node 测试以及 Go 守护服务相关测试，确认注入脚本与 Supervisor 同步链路均无回归。
