# 好友社交菜单与 LAN 移动端设计

## 目标

重构“好友社交”的好友行操作，使高频执行操作和名单配置有清晰边界；统一“本地名单”和游戏协议侧“系统黑名单”的命名。桌面端以两个紧凑菜单承载功能，LAN 手机端以紧凑双按钮和底部抽屉承载相同功能。

本设计已确认的视觉稿：

- 桌面推荐方案：`.superpowers/brainstorm/social-redesign-20260723/content/01-friend-social-layout.html`
- LAN 手机布局：`.superpowers/brainstorm/social-redesign-20260723/content/02-lan-mobile-layout.html`
- LAN 紧凑按钮：`.superpowers/brainstorm/social-redesign-20260723/content/03-lan-mobile-compact-actions.html`

## 范围

涉及 `frontend/src/views/SocialView.tsx`、`frontend/src/views/social/SocialRankingDialog.tsx`、`frontend/src/style.css`、好友社交前后端测试，以及 `internal/farm/social/actions.go` 的一个已有动作别名修复。

不改变好友规则数据结构、自动化筛选语义、协议调用参数、排行榜分页、导入导出文件格式或桌面页面的整体信息架构。

## 名称与语义

| 旧文案 | 新文案 | 含义 |
| --- | --- | --- |
| 查看协议拉黑好友 | 查看系统拉黑 | 查询游戏协议侧的系统黑名单 |
| 协议拉黑好友 | 系统黑名单 | 系统黑名单管理抽屉标题 |
| 协议拉黑 | 系统拉黑 | 系统黑名单行状态 |
| 黑名单 | 本地黑名单 | Farm_Go 本地规则名单 |
| 白名单 | 本地白名单 | Farm_Go 本地规则名单 |
| 黑白名单设置 | 本地名单设置 | 本地规则编辑抽屉 |

本地黑名单和本地白名单沿用现有的独立名单与范围规则；同一好友可以同时存在于两个本地名单中，黑名单在同一生效范围内仍按现有规则优先。此次不隐式移除另一份本地名单。

“系统黑名单”仅指 `gameCtl.blockFriendByProtocol` 和 `gameCtl.getFriendBlockListByProtocol` 所代表的游戏侧关系。Go 类型和方法名中的 `Protocol` 保持技术命名，不暴露到界面。

## 桌面好友行

好友表由五列调整为四列：`好友`、`状态与名单`、`可执行`、`操作`。

- `状态与名单` 合并现有状态和名单的重复胶囊，显示本地黑名单、本地白名单、保护、护主犬、低等级屏蔽。普通状态显示“普通”。
- `可执行` 显示可偷数量、可帮忙、可捣乱等只读状态，不再放执行按钮。
- `操作` 列始终保留两个按钮：主按钮 `操作`，次按钮 `配置`。两者都使用文字加 `ChevronDown` 图标，不能只用图标。
- 每行同一时间只允许一个菜单打开；点击其它行、页面空白处、按 `Escape` 或执行动作后关闭菜单。

### 操作菜单

`操作` 弹出锚定菜单，顺序固定为：

1. 查看
2. 偷菜
3. 捣乱
4. 帮助

“查看”继续调用既有 `enter` 动作，界面不再显示“进入”。其余动作继续使用 `steal`、`mischief`、`help`。不可执行时菜单项置为禁用，并在禁用项旁显示既有状态可推导的原因，例如“当前无可偷作物”或“名单规则已跳过”；不会通过颜色单独表达禁用状态。

### 配置菜单

`配置` 弹出独立的锚定菜单，不与执行操作混排。菜单默认按以下顺序显示：

1. 加入本地黑名单
2. 加入本地白名单
3. 加入系统黑名单

若好友已存在于任一份本地名单，对应项变为“移出本地黑名单”或“移出本地白名单”；另一份名单项仍正常显示。这保留现有 `blacklist_toggle` 和 `whitelist_toggle` 的双名单行为。

“加入系统黑名单”使用警示色与 `Ban` 图标。点击后先显示确认弹层，确认内容包含好友名称和 GID，按钮为“取消 / 加入系统黑名单”。取消不发请求；确认后调用系统拉黑动作并显示现有 toast 结果。系统拉黑不提供行内解除入口，解除操作统一在“查看系统拉黑”中完成。

`FriendRow.protocolBlocked` 不是好友列表刷新时可靠填充的状态，因此普通好友行不为了显示系统状态额外请求系统黑名单。若后续数据已带该字段，可显示“系统拉黑”状态并将配置项改为禁用的“已加入系统黑名单”；否则始终允许通过确认入口发起加入。

## 功能页与系统黑名单管理

“好友功能”中的入口调整如下：

- `查看协议拉黑好友` 改为 `查看系统拉黑`。
- `清理无效黑名单` 改为 `清理无效本地黑名单`。
- `批量移除黑名单/白名单` 改为 `批量移除本地黑名单/本地白名单`。
- `黑白名单设置` 改为 `本地名单设置`。

系统黑名单抽屉标题为“系统黑名单”。其中的说明、空状态、选择标签与解除按钮统一使用“系统拉黑”，例如“暂无系统拉黑好友”“解除系统拉黑”。保留批量选择、全选、清空、单项解除以及请求中禁用逻辑。

本地名单设置、批量移除、导入导出和摘要指标中的用户可见“黑名单/白名单”全部加“本地”前缀，避免与系统黑名单混淆。底层 `blacklist`、`whitelist` 字段、导出文件名和 JSON 格式不改变。

排行榜中的协议拉黑按钮也改为“加入系统黑名单”，与好友行配置菜单复用相同确认流程。

## 动作映射与接口修复

前端目前排行榜调用的 `protocol_block` 在 `internal/farm/social/actions.go` 中没有匹配分支，而后端已有可用的 `block_friend` 分支。实施时将所有“加入系统黑名单”界面入口统一发起 `block_friend`；后端协议方法、参数、返回格式不改。

| UI 命令 | 前端动作 | 后端/协议行为 |
| --- | --- | --- |
| 查看 | `enter` | 进入好友农场 |
| 偷菜 | `steal` | 现有好友偷菜流程 |
| 捣乱 | `mischief` | 现有好友捣乱流程 |
| 帮助 | `help` | 现有好友帮助流程 |
| 加入/移出本地黑名单 | `blacklist_toggle` | 保存本地规则 |
| 加入/移出本地白名单 | `whitelist_toggle` | 保存本地规则 |
| 加入系统黑名单 | `block_friend` | `gameCtl.blockFriendByProtocol` |
| 解除系统拉黑 | `unblock_friend` / 批量动作 | 现有解除协议拉黑流程 |

执行完本地名单动作后保留 `AuthorizedApp` 的社交刷新策略。系统拉黑成功后同样刷新好友社交和当前打开的系统黑名单列表（若存在），保证按钮和 toast 结果一致。

## LAN 移动端

只在 `.app-shell-remote` 且视口宽度不超过 `760px` 启用；桌面锚定菜单、普通应用窗口和既有 LAN 顶部操作布局保持不变。

### 好友卡

保留现有的纵向好友卡，而非恢复横向表格：

- 左侧为好友名、GID、等级、本地名单/保护状态和可执行状态。
- 右侧改为一行并列的 `操作`、`配置` 紧凑按钮，不再纵向堆叠。
- 右侧操作区宽度约 `114px`，两个视觉按钮各约 `55px` 宽、`32px` 高，间距 `4px`。
- 每个视觉按钮外层保留至少 `42px` 高的触控热区，点击整个热区都可打开抽屉。
- 好友卡目标高度约 `70px`；内容较多时允许左侧标签自然换行，按钮区不跟随拉高。
- 不显示下拉箭头，以减少窄屏噪音；点击按钮直接打开抽屉。

搜索和排序维持一行；筛选胶囊继续水平滚动。摘要指标继续使用三列两行，不引入横向页面滚动。

### 移动命令抽屉

LAN 手机端不使用桌面锚定浮层。`操作` 和 `配置` 都复用现有 `.social-dialog` 的底部抽屉合同：底部对齐、顶部圆角、清晰关闭按钮、好友名称和 GID 上下文、正文单独滚动。

抽屉内每个命令行至少 `42px` 高，带 Lucide 图标与文字标签。`操作` 抽屉显示四个命令；`配置` 抽屉显示三个名单命令和动态的本地移除状态。系统黑名单的确认弹层从该抽屉继续展开，取消后回到配置抽屉。

现有好友功能、本地名单设置、批量移除、护主犬、系统黑名单、封神榜、导入导出和排行榜继续使用既有 LAN 底部抽屉规则，不做全屏对话框回退。

## 可访问性与状态

- 桌面菜单触发按钮使用 `aria-haspopup="menu"`、`aria-expanded` 和关联菜单 ID；菜单项按视觉顺序可用键盘聚焦。
- `Escape` 先关闭确认层，再关闭命令菜单；点击遮罩或外部区域关闭未确认菜单。
- 视觉按钮必须有可见文字；所有图标只做辅助，不传递唯一含义。
- 禁用、运行中、失败和成功状态沿用现有 toast 与按钮禁用机制，并补充文字而不是只改变颜色。
- “加入系统黑名单”必须经过确认。单次请求进行中时，该好友的相关菜单项禁用，避免重复提交。

## 实施边界

前端新增小型、职责清晰的组件或同文件局部组件：桌面行菜单、移动命令抽屉、系统拉黑确认层。它们仅接收 `FriendRow`、当前本地规则、打开/关闭状态和 `onAction`，不自行调用 Wails 或存储。

实现可复用现有 `Dialog`、`FeatureButton`、`Pill` 和 Lucide 图标；移除仅服务旧五枚图标按钮的 `IconAction` 与其 LAN 样式。样式新增在当前 `.app-shell-remote` 社交手机段附近，避免影响非 LAN 桌面布局。

## 测试与验收

前端测试覆盖：

1. 好友行只渲染“操作 / 配置”两类入口，操作菜单含查看、偷菜、捣乱、帮助。
2. 配置菜单含三种加入动作；本地成员状态正确切换为移出文案，不会自动移除另一份本地名单。
3. 文案不再出现面向用户的“协议拉黑”“黑白名单设置”或裸“黑名单/白名单”指代本地规则。
4. 系统拉黑确认层只有确认后才发送 `block_friend`，排行榜与好友行共用该动作。
5. LAN 手机样式下好友操作区为横排紧凑控制，视觉按钮 `32px`、触控外层至少 `42px`，无旧 `.social-icon-action` 样式依赖。
6. LAN 抽屉仍具有固定标题、关闭按钮、滚动正文和可触达的确认操作。

后端测试覆盖：`block_friend` 继续调用既有协议方法；前端不再传递未被 `Service.Action` 支持的 `protocol_block`。原有本地名单、批量解除系统拉黑和保护好友测试必须保持通过。

验收时在桌面宽度、`760px` 和 `360px` LAN 视口检查：菜单不会溢出或遮挡其它好友行；移动好友卡不会横向滚动；按钮不再呈现纵向大块；系统黑名单操作有确认且解除入口仍可用。

## 非目标

- 不改变本地黑白名单的范围选择、优先级或存储格式。
- 不将系统黑名单缓存合并进每次好友列表刷新。
- 不增加批量加入系统黑名单。
- 不重做排行榜、护主犬、导入导出或自动化页面。
