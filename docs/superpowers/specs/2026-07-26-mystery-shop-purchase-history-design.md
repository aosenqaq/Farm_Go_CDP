# 神秘商店自动购买与购买记录设计

## 目标

优化神秘商店自动购买设置面板，补齐金豆豆货币选项，并为每个运行账号保存可查看的成功购买记录。

## 范围

- 允许货币增加金豆豆，货币 ID 为 `1005`。
- 仅在神秘商店购买协议返回成功后写入购买记录。读取商品、无匹配商品、调用错误和协议失败均不写入记录。
- 记录与当前运行账号的 `account_key` 绑定，账号切换后只展示该账号记录。
- 设置面板展示当前账号最近 50 条记录，不提供删除、筛选、分页或失败尝试历史。

## 数据设计

新增 SQLite 表 `mystery_shop_purchase_records`，以 `(account_key, id)` 为主键，并按 `account_key, occurred_at DESC, id DESC` 建索引。

每条记录包含：

- 唯一 ID、账号键和 RFC3339Nano 购买时间；
- 商品 ID、商品名称、数量；
- 单价、货币 ID、货币名称和折扣；
- 可选的原始商品卡 JSON，供排查协议字段变化。

存储层提供追加单条记录和按账号倒序读取最近记录的方法。写入沿用账号键标准化规则；读取上限固定为 50。存储写入失败不会把已确认成功的购买改为失败，而是由调用方记录错误事件。

## 运行流程

1. 自动或手动触发 `mystery_shop_auto_buy`，读取当前商店卡片并按现有货币、折扣规则选卡。
2. 调用购买协议；仅当协议返回成功时，从被选卡片提取商品、数量、价格、货币和折扣。
3. 通过运行账户的存储适配器追加记录。记录成功后仍返回现有成功语义；记录写入异常写入运行事件但不回滚购买结果。
4. 应用层新增只读 RPC `FarmMysteryShopPurchaseRecords()`，只返回当前账户最近 50 条购买记录；自动化视图加载设置页和购买完成后调用该接口以显示最新记录。

运行时 facade 增加一个窄的购买记录写入接口，并沿用现有社交记录适配器的账户键注入方式。这样纯运行时单元测试仍可使用空存储，而应用路径负责将 SQLite 存储传入 facade。

## 界面设计

在“神秘商店自动购买”设置中保持现有浅色、紧凑的工具面板风格，重新组织为三个连续区域：

1. 顶部操作栏：读取当前神秘商店商品和价格、按预设自动购买；最新执行结果紧随操作按钮显示。
2. 购买规则：双列显示自动购买间隔和折扣阈值；下方以四等分复选项展示金币、点券、钻石、金豆豆，移动端自然换行。
3. 购买记录：标题标明“当前账号”和“最近 50 条”，按时间、商品与数量、支付信息三列展示。每行支付信息显示货币和价格，并在有折扣时显示折扣。无记录时给出紧凑空状态，避免大面积留白。

记录区随设置面板滚动，在窄屏改为纵向信息排列，保证时间、商品和支付信息不截断。

## 测试

- 存储：记录可回读、按账号隔离、按最新时间排序并受 50 条上限约束。
- 运行时：购买成功时写入完整记录并传入当前账号；无匹配、购买失败和读取失败均不写入；记录写入失败不改变购买成功结果。
- 应用：购买记录 RPC 只返回当前账号的数据，账号切换后不泄漏其他账号记录。
- 前端：金豆豆复选项使用 ID `1005`；设置面板展示记录标题、记录行和空状态；成功购买后状态刷新。

## 非目标

- 不保存失败、跳过或仅读取的操作。
- 不改动购买选择顺序、折扣逻辑或既有默认货币配置。
- 不增加跨账号汇总、导出、清空或历史筛选功能。
