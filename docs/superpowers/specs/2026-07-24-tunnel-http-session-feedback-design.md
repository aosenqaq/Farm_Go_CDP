# 安全隧道 HTTP 会话提示设计

日期：2026-07-24

## 背景

安全隧道模式的浏览器控制台只应通过 FRP 的 HTTPS 公网入口访问。服务在该模式下签发 `Secure` 会话 Cookie；当用户通过 `http://FRP-IP:端口` 访问时，浏览器会拒收该 Cookie。密码校验请求可能已成功，但紧随其后的会话检查未携带 Cookie，前端因此显示了不准确的“访问密码验证失败”。

## 目标

在不降低安全隧道会话安全性的前提下，阻止 HTTP 页面提交访问密码，并明确提示用户改用 HTTPS FRP 入口。局域网模式的 HTTP 浏览器访问必须维持原有行为。

## 非目标

- 不允许安全隧道以 HTTP 使用非 `Secure` Cookie。
- 不内置、托管或自动配置 FRP、证书或 TLS。
- 不修改密码哈希、会话有效期、CSRF、来源校验或隧道来源限制。

## 方案

### 模式标记

`internal/lanaccess/server.go` 的外部启动脚本继续设置现有的 `window.__FARM_GO_REMOTE__`。服务处于安全隧道模式时，脚本额外设置 `window.__FARM_GO_TUNNEL__=true`；局域网模式不设置该标记。该标记仅用于浏览器的提示和提交前校验，服务端认证边界保持不变。

### 浏览器行为

`frontend/src/RemoteApp.tsx` 在提交访问密码前读取浏览器地址协议与隧道标记：

- 安全隧道且地址不是 `https:`：不发送 `/api/auth/login` 请求，保留密码门，并显示“安全隧道必须通过 HTTPS FRP 入口访问”。
- HTTPS 安全隧道：沿用当前登录、会话同步和远程控制台流程。
- 局域网 HTTP：不受影响，继续允许提交密码与建立会话。

前端远程环境类型会扩展为可选的 `__FARM_GO_TUNNEL__` 属性，以保持类型约束并避免对桌面 Wails 运行时作出假设。

### 设置文案

设置面板将模式选项由“安全隧道（127.0.0.1）”调整为“安全隧道（仅 HTTPS）”。运行状态显示的 `127.0.0.1:<port>` 仍是 FRP 的本机目标，不是浏览器访问地址。

## 错误处理

HTTP 安全隧道在发送密码前被阻止，因此不会把传输配置问题误报为密码错误，也不会在非加密连接上传输访问密码。其他登录错误继续使用既有错误处理，避免扩大行为范围。

## 测试

- Go 服务测试：局域网启动脚本只有远程标记；隧道启动脚本还包含隧道标记。
- React 测试：隧道标记与 `http:` 地址下提交表单不会调用 `fetch`，并显示 HTTPS 提示。
- React 回归测试：HTTPS 隧道和局域网 HTTP 仍走现有登录请求。
- 运行受影响的 Go、前端单测与前端构建，确认无类型或打包回归。

## 验收标准

1. 使用 `http://FRP-IP:端口` 访问安全隧道时，用户看到 HTTPS 配置提示，且浏览器不会提交访问密码。
2. 使用 HTTPS FRP 入口访问安全隧道时，成功密码仍能进入控制台。
3. 局域网 HTTP 登录保持可用。
4. 安全隧道 Cookie 仍保留 `Secure`、`HttpOnly` 和 `SameSite=Strict` 属性。
