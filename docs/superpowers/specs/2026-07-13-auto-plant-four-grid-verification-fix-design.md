# 自动种植四格分组与校验失败修复设计

## 背景

自动种植任务在开启四格种植、农场存在大量空地时返回
`plant_verify_failed`。当前微信 CDP 链路的现场数据表明：

- 农场共有 20 块可种植空地；
- 背包首项为四格种子 `21032`；
- 土地 `[1,2,3,4]` 位于同一行，不构成 2x2；
- 首个有效 2x2 是 `[1,2,5,6]`；
- 单块、双块和 16 块普通种植均能通过同一运行时接口成功。

因此，问题不是种子 ID、批量请求数量或 300ms 校验窗口，而是四格土地在
Go 端按数量切片，没有按网格位置分组。JavaScript 端随后将
`no_complete_multi_land_group` 覆盖成 `plant_verify_failed`，使 Go 端已有的
普通种子回退分支无法执行。

## 目标

1. 四格种子只分配到真实、完整且互不重叠的 2x2 空地。
2. 当前空地不能组成 2x2 时，跳过四格种子并继续使用普通种子补种。
3. 保留真正的种植后状态校验失败，不把所有失败都降级为跳过。
4. 不改变自动种植策略顺序、用户配置或普通种子的种植行为。

## 方案

### 空地排序

Go 端继续通过 `gameCtl.getFarmStatus` 获取网格。新增自动种植专用的空地排序：

1. 过滤 `stageKind == "empty"` 且 `interactable == true` 的网格。
2. 使用 `gridPos.x` 和 `gridPos.y` 建立位置索引。
3. 按稳定位置顺序寻找由 `(x,y)`、`(x+1,y)`、`(x,y+1)`、
   `(x+1,y+1)` 组成的完整分组。
4. 每块土地最多进入一个分组。
5. 返回时先依次放置完整分组的四块土地，再追加未分组土地。

现有背包计划器按四格种子库存取 `count * 4` 块土地，因此排序后每次切片都会
落在完整分组边界上。普通种子继续消费剩余土地。

当四格种植未启用时，仍使用现有按土地 ID 排序的行为。

### 失败原因透传

`plantSeedsOnLandsVerified` 在派发前若收到 `plantSeedsOnLands` 返回的
`planted: false` 和 `reason: no_complete_multi_land_group`，立即返回相同原因，
不进入种植后空地差值校验。

Go 端现有的 `autoPlantFailureReason` 会识别该原因，回收本计划土地并交给后续
普通种子。其他已经派发过请求但状态未变化的情况仍返回
`plant_verify_failed`。

## 数据流

1. `runOwnPlant` 读取包含 `gridPos` 的农场状态。
2. 空地收集器按完整 2x2 分组优先排列土地 ID。
3. `resolveBackpackFirstPlantPlans` 按种子库存分配土地。
4. `gameCtl.autoPlant` 对四格计划校验并派发多格事件。
5. 无完整分组时，JavaScript 返回明确原因。
6. Go 端跳过该四格计划，将土地交给普通种子计划。

## 错误处理

- 无完整 2x2：预期分支，不使任务失败，继续普通种子。
- 种植事件已派发但土地状态未变化：保留 `plant_verify_failed`。
- CDP 调用失败、农场状态不可读或普通种子种植失败：保持现有失败语义。
- 所有计划均因无完整 2x2 被跳过且没有普通种子：保持现有成功跳过消息。

## 测试

### Go 回归测试

- 全空 4 列农场中，四格计划首组选中 `[1,2,5,6]`，而不是
  `[1,2,3,4]`。
- 多个可用 2x2 时生成互不重叠的稳定分组。
- 无完整 2x2 时，四格失败后普通种子接管原土地。
- 未开启四格种植时保持现有土地 ID 排序。

### JavaScript 脚本契约测试

- 在现有读取 `resources/wmpf/button.js` 的 Go 测试模式中，验证
  `no_complete_multi_land_group` 在种植后差值校验前原样返回。
- 验证已经派发请求但状态未变化的路径仍保留 `plant_verify_failed`。

完整回退行为由 Go 运行时门面测试覆盖，真实脚本行为由当前微信 CDP 链路验证。

### 现场验证

在当前 `wails dev` 和微信 CDP 链路中制造至少一组空地，运行 `own_plant`：

- 有完整 2x2 时，四格种子种在完整分组上；
- 无完整 2x2 时，普通种子继续补种；
- 任务日志不再因分组失败显示 `plant_verify_failed`。

## 非目标

- 不调整种子策略排序或背包优先级。
- 不改变施肥、收获或其他自动化任务。
- 不增加新的用户设置。
- 不重构通用运行时调用接口。
