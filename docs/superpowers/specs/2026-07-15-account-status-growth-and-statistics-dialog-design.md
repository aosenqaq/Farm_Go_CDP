# 账户状态成长概览与运行统计弹窗

## 目标

优化账户状态页面的信息层级：将角色成长信息作为账户资产的核心信息展示，并将低频查看的运行统计收纳到弹窗中，同时保留已有统计范围和统计卡设计。

## 页面结构

账户状态页顶部保留标题、说明与刷新账户按钮。刷新按钮旁增加带图标的“运行统计”按钮。

主内容由账户资产主卡和下方双列卡片组成。下方左侧为肥料容器，右侧为活动货币。运行统计不再作为页面内区块。

账户资产区顶部使用成长主卡：

- 显示昵称与当前等级。
- 显示“经验升级进度”、当前经验与本级所需经验。
- 显示可访问的原生进度条，宽度由百分比控制。
- 显示下一等级和距升级剩余经验。
- 下方保留金币、金豆豆、点券、钻石四项资产卡。

肥料容器继续显示无机与有机肥料的剩余时间，不改变其数据来源和计算方式。

活动货币卡位于原运行统计卡的位置，显示当前活动物品“荷露”、其仓库类型标签和数量。数量使用仓库快照中名称精确为“荷露”的物品的 `count`。首次打开账户状态页与用户点击“刷新账户”时，前端并行调用既有的 `FarmWarehouse` 接口读取当前仓库快照；不复制仓库解析、物品映射或数量计算逻辑。

仓库请求失败、请求仍在进行、仓库状态不可用或快照中未出现“荷露”时，活动货币卡显示“暂未获取”，不得将未知数量显示为 `0`。活动货币卡不提供出售或跳转操作。

## 运行统计弹窗

点击“运行统计”打开模态弹窗；按 Escape、点击关闭按钮或点击遮罩关闭。打开时焦点移入弹窗，关闭时归还给触发按钮。

弹窗沿用当前统计功能：

- 今天、近三天、近七天、近十五天、近三十天五个范围按钮。
- 运行次数、收获、务农、偷菜、好友帮忙、好友捣乱、出售、覆盖天数八项指标。
- 原有按自然日聚合与覆盖天数计算保持不变。

弹窗打开期间不重新拉取账户数据；刷新账户后，已打开的弹窗使用新的资料重新计算并渲染统计结果。活动货币读取与统计弹窗互不依赖。

## 数据与降级

前端继续使用 `profile.levelProgress`，其字段由现有运行时账户接口提供：`current`、`needed`、`remaining`、`percent` 与 `nextLevel`。

若当前经验和本级所需经验均为有效的非负数，显示经验数值和进度条。百分比限制在 0 到 100；后端已完成相同限制，前端再次限制以保护 UI。

若经验数据缺失或所需经验不大于 0，成长主卡保留昵称和等级，但显示“经验数据暂不可用”，并隐藏进度填充、剩余经验和下一等级的推导信息。页面不得用猜测数据补齐。

## 可访问性与样式

沿用当前深绿侧栏、暖白背景、细边框和亮绿状态色。弹窗使用语义化 `role="dialog"`、`aria-modal="true"` 与明确标题关联；图标按钮有中文 `aria-label`。

进度条使用 `role="progressbar"` 并声明当前值、最小值和最大值。统计范围按钮保留清晰的激活状态。

## 验证

新增或更新账户状态视图渲染测试，覆盖：

- 有完整经验数据时的进度数值、百分比与下一等级提示。
- 缺失经验数据时的降级文案和无进度填充。
- 点击统计按钮后弹窗包含原有范围和八项指标，并可关闭。
- 仓库快照含“荷露”时显示其数量；缺失、加载中或仓库错误时显示“暂未获取”，且不显示伪造的 `0`。
- 原有运行时未就绪提示、肥料显示及统计聚合测试继续通过。

运行受影响的前端测试、完整前端测试与前端构建。构建后确认 `public/app/index.html` 引用了新生成的资源文件。
