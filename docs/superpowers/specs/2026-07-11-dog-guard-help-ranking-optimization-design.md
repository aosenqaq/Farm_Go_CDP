# 护主犬、好友帮助与排行榜优化设计

## 目标

本次优化统一护主犬扫描、好友帮助和社交记录展示的数据来源与交互方式：

- 精简护主犬扫描参数，固定扫描全部当前好友，并增加默认 `300ms` 的好友间扫描间隔。
- 扫描完成后主动提示结果，复用好友列表现有状态标记，并同步顶栏护主犬数量。
- 为好友帮助增加“仅帮助护主犬好友”，使用当前账户已持久化的有效护主犬名单。
- 将好友帮助改造成最大并发 `3` 的批处理任务。
- 统一偷取、被偷和访客记录的队列布局，并为偷取记录增加列表与排行榜双模式。

## 范围

本设计只调整以下现有模块：

- 护主犬扫描请求、扫描器状态与扫描界面。
- 当前账户社交缓存、好友状态和社交顶栏统计。
- 农场自动化中的好友帮助配置与执行逻辑。
- 社交排行榜偏好、记录转换和记录列表布局。

不新增自动护主犬扫描，不改变偷菜协议，不改变好友黑白名单规则，也不增加可配置的帮助并发参数。

## 账户级护主犬数据

护主犬扫描结果继续使用现有社交缓存，并以标准账户键 `gid:<账户GID>` 持久化。扫描器、社交服务和自动化任务必须使用同一个账户键读取数据。

缓存可以保留历史扫描行，但所有面向当前界面的有效数据都必须使用当前好友列表取交集：

1. 读取当前账户的好友列表。
2. 读取同一账户的护主犬缓存。
3. 仅保留当前仍是好友且 `hasGuardDog` 为真的 GID。
4. 使用该有效集合生成好友状态标记、顶栏数量和仅护主犬帮助候选人。

切换账户时，前端重新加载目标账户的社交状态和护主犬状态。旧账户缓存不得参与新账户的计数、开关可用性或自动化执行。

## 护主犬扫描

### 请求参数

从前后端移除以下参数：

- 扫描数量 `limit`。
- 进入好友等待 `enterWaitMs`。
- 读取前等待 `afterEnterWaitMs`。

新增扫描间隔 `scanIntervalMs`，默认值为 `300`。非正数使用默认值，超过 `60000ms` 时限制为 `60000ms`。该间隔只发生在相邻好友扫描请求之间，首位好友不需要预等待。

扫描范围固定为全部当前好友，并继续支持：

- 跳过已扫描。
- 排除已发现护主犬。

这两个选项只过滤扫描候选人，不改变“固定扫描全部”的基础含义。

### 执行与状态

扫描继续以异步串行任务执行：

1. 刷新并读取当前好友列表。
2. 应用跳过和排除规则。
3. 逐个调用现有好友农场检查协议。
4. 每完成一名好友立即更新并持久化扫描行。
5. 若还有下一名好友，则等待 `scanIntervalMs`。
6. 完成、停止或失败后写入唯一的 `finishedAt`。

停止扫描时保留已经完成的结果。清空操作只清除当前账户缓存，并触发社交状态重新计算。

### 标记、数量与完成提示

好友列表继续使用现有 `Pill` 状态标记显示“护主犬”，与“低等级屏蔽”等状态处于同一列，不创建新的标记组件。

社交顶栏的护主犬数量只统计当前好友列表中的有效护主犬好友。扫描、停止、清空、好友刷新或账户切换后都要重新计算该数量。

前端通过 `running: true -> false` 的状态变化和新的 `finishedAt` 判断一次扫描结束，避免轮询重复提示。只有自然完整结束才显示右下角成功提示：

> 已扫描到 xxx 名护主犬好友，已自动标记

手动停止不显示成功提示。扫描失败显示现有错误结果样式。

## 仅帮助护主犬好友

新增账户级自动化布尔配置 `autoFarmFriendHelpGuardDogOnly`，默认关闭，并使用现有账户级自动化设置持久化。

当前好友列表中有效护主犬数量为 `0` 时：

- 开关灰色且不可操作。
- 界面显示简短原因“请先读取护主犬好友”。
- 如果账户切换、好友刷新或清空缓存使数量归零，前端草稿值自动恢复为关闭。
- 后端执行时仍做相同校验，防止旧配置或直接调用绕过前端限制。

开启后，帮助候选人的筛选顺序为：

1. 从当前好友列表选出存在帮助工作量的好友。
2. 与当前账户有效护主犬 GID 集合取交集。
3. 应用现有好友帮助规则和每批好友数量上限。

未开启时保持现有候选范围，不受护主犬缓存影响。

## 好友帮助并发

保留现有“每批帮助好友数量”作为候选数量上限。任务内部使用固定最大并发 `3` 的工作池，不增加新的并发配置项。

每个候选好友由一个工作单元完成完整序列：

1. 协议检查好友农场并收集可帮助地块。
2. 没有可帮助地块时记录为跳过。
3. 有可帮助地块时调用现有好友帮助协议。
4. 记录该好友的成功、跳过或失败结果。

最多同时处理三名好友。单个好友失败不取消其他工作单元，也不提前结束整批任务。最终结果稳定地按候选好友原顺序汇总，并报告成功好友数、帮助项数、跳过数和失败数。

如果启用了仅护主犬模式但当前账户没有有效护主犬好友，任务返回成功跳过结果，并明确提示需要先读取护主犬好友，不回退到帮助全部好友。

## 排行榜与记录队列

### 显示模式

- 偷取记录：列表模式和排行榜模式。
- 被偷记录：列表模式和排行榜模式。
- 访客记录：仅列表模式。

排行榜偏好扩展为两个账户级字段：

- `stolenByMeViewMode`。
- `stolenFromMeViewMode`。

两个字段都只接受 `timeline` 或 `ranking`，缺失或非法值回退到 `timeline`。保存时沿用当前账户作用域和过期请求保护。

### 统一队列

三个标签统一采用以下列顺序：

1. 时间。
2. 好友名称。
3. 详情。

列表模式每条事件独占一行并按时间倒序。排行榜模式按好友聚合和次数排序，时间列显示该好友最近一次记录时间，好友列同时显示名次，详情列显示总次数和汇总内容。

详情内容：

- 偷取记录：偷取次数、作物名称和数量。
- 被偷记录：被偷次数和损失汇总。
- 访客记录：规范化后的访问行为。

桌面端使用稳定的三列网格，时间列和好友列保持固定响应式约束，详情列占用剩余空间。窄屏按相同顺序纵向排列。长名称和长详情使用换行或省略策略，不能覆盖相邻内容。

## 前端数据流

应用层继续持有社交状态、护主犬状态和自动化状态，并将当前社交状态中的有效护主犬数量传给自动化视图。

自动化视图只用该数量控制开关的可用状态；真正的候选 GID 不复制到前端配置中。自动化后端在任务执行时从当前账户缓存读取名单，从而保持唯一数据来源。

扫描完成提示由社交视图根据扫描状态变化生成，并使用现有右下角结果提示样式。排行榜模式切换继续采用乐观更新、后端保存和失败回滚。

## 异常与一致性

- 扫描器和自动化任务都固定使用任务启动时的账户键。
- 账户切换后的旧异步结果不能覆盖新账户界面状态。
- 护主犬缓存读取失败时，仅护主犬帮助不得回退到全部好友。
- 并发帮助中的单项错误被汇总，不覆盖其他成功结果。
- 扫描完成提示以 `finishedAt` 去重，同一任务只显示一次。
- 清空当前账户护主犬缓存后，好友标记、顶栏数量和帮助开关必须同步归零或关闭。

## 测试与验收

### 后端测试

- 扫描请求默认使用 `300ms` 间隔并扫描全部候选好友。
- 已移除参数不再影响扫描器行为。
- 扫描间隔只发生在相邻好友之间。
- 护主犬缓存按账户 GID 隔离。
- 有效护主犬数量只包含当前好友交集。
- 仅护主犬帮助只处理有效标记好友。
- 无有效护主犬好友时任务明确跳过。
- 好友帮助最大并发不超过 `3`。
- 单个好友失败时其他候选人仍继续执行。
- 汇总结果按候选好友原顺序稳定输出。
- 两种排行榜偏好按账户保存并规范化。

### 前端测试

- 护主犬扫描界面只显示扫描间隔、跳过已扫描和排除已发现护主犬。
- 扫描间隔默认显示 `300`。
- 完整扫描结束只出现一次成功提示。
- 手动停止和失败不显示成功提示。
- 好友列表使用现有护主犬状态标记。
- 顶栏数量随扫描、清空、刷新和账户切换同步。
- 没有有效护主犬好友时帮助开关不可勾选。
- 有有效护主犬好友时开关可用并保存账户级配置。
- 偷取和被偷记录均可切换列表与排行榜模式。
- 访客记录不显示排行榜模式开关。
- 三类记录都按“时间、好友、详情”顺序渲染。
