# 自动种植执行节奏与随机顺序设计

## 目标

使自动种植的随机地块顺序和随机种植延迟实际生效，同时保持本轮策略、背包和种子分配只解析一次。随机延迟的粒度是相邻播种动作之间，而不是整轮任务之前或之后。

## 已确认的行为

- 关闭随机土地顺序时，普通作物严格按已规划空地序列播种。例如空地顺序为 `1, 2, 3, 4, 5, 6, 8`，播种顺序必须相同。
- 开启四格种植时，完整 `2x2` 空地组优先于普通空地；每组内部保持既有协议要求的地块顺序。
- 开启随机土地顺序时，随机调整播种执行单元的顺序，不重新决定不同种子分别种在哪些地块。普通作物的单块地是一个执行单元，四格作物的完整 `2x2` 组是一个执行单元。
- 开启随机种植延迟时，首个执行单元立即播种；每个后续执行单元前随机等待一次，范围为闭区间 `[minMs, maxMs]`；最后一个执行单元后不增加随机等待。
- 延迟开关不改变播种顺序。关闭随机顺序、开启延迟时，仍严格保持已规划的顺序。
- 同一轮种植只解析一次策略、农场空地、背包种子和商店候选；延迟期间不得重新读取策略或背包，也不得重新规划地块与种子的对应关系。

## 现状与根因

前端配置会经 Go 的 `baseOwnPlantOptions` 传递到 `gameCtl.autoPlant`，但运行时未消费 `autoPlantRandomizedEnabled`、`autoPlantRandomizedDelayMinMs`、`autoPlantRandomizedDelayMaxMs` 和 `autoPlantRandomOrderEnabled`。普通地块当前在 `plantSeedsOnLands` 中同步循环派发；唯一的等待位于全量派发后的验证阶段。因此两个设置都没有运行时效果。

## 推荐架构

保留 Go 层的计划职责，改造 JavaScript 运行时的执行职责。

1. Go 层继续读取一次农场状态，并通过现有主/副策略和背包分配生成一个或多个种植计划。每个计划已经绑定种子和 `emptyLandIds`。
2. `gameCtl.autoPlant` 继续对每个种植计划只调用一次，解析该计划的种子信息一次。
3. 运行时根据该计划和作物尺寸构建执行单元：普通作物为单地块单元，四格作物为完整 `2x2` 单元。
4. 运行时按配置选择顺序：关闭随机顺序时保留输入顺序；开启时以 Fisher-Yates 随机打乱执行单元，四格组不可拆分。
5. 运行时顺序派发每个执行单元，在相邻单元之间按配置等待。全部派发后，沿用现有的种植状态校验和奖励关闭流程。
6. Go 层在调用运行时前，按计划地块数和随机延迟最大值计算调用超时：`60 秒 + (地块数 - 1) * maxMs`，总时长最多 15 分钟；同时把同一截止时间传给运行时，避免调用方超时后运行时继续派发。

该分层避免把单个地块拆成多次 `gameCtl.autoPlant` 调用；后者会重复空地校验、种子显示名解析、奖励处理和结果验证，且会让种后施肥被不必要地拆成多批。

## 四格和施肥

- 四格模式下，随机排序只调整完整组之间的顺序；组内仍使用 `orderMultiLandPlantGroupForDispatch` 的协议顺序。
- 延迟以一组四格的单次协议派发为一个间隔单位，不会在同组四块地之间插入等待。
- 运行时在整个计划完成后返回现有的种植结果；Go 层继续在成功后仅调用一次对应的批量施肥，不重新读取农场状态。

## 配置与错误处理

- 前端保存时校验种植随机延迟的最小值和最大值均为非负整数，且 `maxMs >= minMs`。
- 运行时也执行防御性归一化，以兼容历史配置或绕过前端的调用：关闭开关时不等待；负值归零；最大值小于最小值时使用最小值。
- 单次随机延迟上限固定为 `10,000ms`。前端拒绝超出范围的值；运行时将历史配置或绕过前端的值截断到该上限。
- Go 调用和运行时共享上述截止时间；运行时在每次等待前和每次派发前检查截止时间。截止后停止后续派发并返回 `plant_execution_timeout`，不能继续在后台播种。
- 四格找不到完整组、协议派发异常和种植状态验证失败，保持既有错误语义。

## 可观测性

运行时结果增加不含敏感信息的执行摘要：实际执行顺序、执行单元数量、每次实际等待毫秒数、随机顺序和随机延迟是否启用。自动化任务日志使用摘要，不记录原始运行时对象或背包数据。

## 测试

- 运行时 VM 测试验证关闭随机顺序时的普通地块顺序严格不变。
- 运行时 VM 测试验证开启随机延迟时有且仅有 `N - 1` 次等待，且每次在配置范围内；关闭开关时没有随机等待。
- 四格测试验证组优先、组内协议顺序不变，并且随机化从不拆开一个 `2x2` 组。
- Go 自动化测试验证策略和背包查询每轮只发生一次，运行时只收到每个种子计划的一次 `gameCtl.autoPlant` 调用。
- Go 自动化测试验证动态超时覆盖最大地块数和最大延迟。
- 前端测试验证非法随机延迟范围不能保存，正常范围可保存。
- 保留并运行既有四格、种后施肥和自动种植失败回归测试。
