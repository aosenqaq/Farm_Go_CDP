# 运行账号识别弹窗刷新提示栏设计

## 目标

将运行账号识别弹窗右上角仅用于展示状态的图标，改为明确、始终可见的重新识别入口，让用户在账号识别错误或失败时能直接发起重新识别。

## 界面设计

- 在弹窗顶部使用一条横向浅绿色提示栏，替代原右上角状态图标。
- 提示栏包含 `RefreshCw` 刷新图标和文案“如果识别错误/失败，可以点击这里重新识别”。
- 整条提示栏均为可点击按钮，而不只让图标可点击。
- 提示栏与现有米白色弹窗、亮绿色主操作保持一致，圆角不超过现有弹窗的 10px。
- 头像、昵称、识别说明、GId 和“确认进入”按钮保持原有顺序与视觉层级。
- 删除错误状态下底部重复出现的“重新识别”按钮，避免同时出现两个相同操作入口。

## 状态与交互

- 正常识别结果：顶部提示栏可点击，点击后调用现有 `onRetry` 回调。
- 识别失败：顶部提示栏仍是唯一重新识别入口，错误信息继续在账号信息下方展示。
- 正在识别：提示栏显示旋转的加载图标，按钮禁用，文案保持不变，避免重复触发。
- 正在确认：不改变现有确认按钮行为；重新识别入口不额外改变确认流程。
- 点击重新识别后沿用现有父组件逻辑，清空旧识别结果并重新请求运行账号信息。

## 组件边界

本次仅修改 `AccountIdentityDialog` 的结构、样式及对应组件测试。父组件 `AuthorizedApp` 已提供完整的 `onRetry` 行为，无需修改后端接口或账号识别数据流。

## 测试与验收

- 组件测试验证正常识别状态也展示最终提示文案和刷新图标。
- 组件测试验证错误状态只保留一个重新识别入口。
- 组件测试验证识别中提示栏处于禁用状态并显示加载状态。
- 运行相关前端测试与完整前端构建。
- 在桌面和窄屏视口检查文案不溢出、不遮挡头像，按钮点击区域清晰，错误信息与确认按钮无重叠。
