# Farm_Go Wails 第一阶段 UI 设计说明

## 设计结论

Farm_Go 第一阶段采用“精致桌面诊断站”的 UI 方向：

- 视觉方向：成熟的 Windows 桌面工具，不做浏览器后台感，也不做临时开发面板感。
- 首页结构：状态优先，诊断操作放在二级页面。
- 文案基调：界面全中文。`QQ WS`、`host.describe`、`gameCtl.probe` 这类协议和运行时标识保留原文，因为它们是实际调用名或技术对象名。

这个方向服务第一阶段目标：用户打开 `Farm_Go.exe` 后，可以直接看到本机运行时状态、QQ WS 连接状态、最近事件，并能进入诊断页执行探测调用。

## 产品气质

应用应像一个小而完整的本地诊断工作台：

- 日常反复使用时足够安静。
- 第一眼像完成度较高的桌面产品。
- 对技术用户足够明确，但不把所有实现细节堆在首页。

视觉采用已确认的“精致桌面工具”方向：

- 主画布使用温暖的米白色。
- 左侧使用深色常驻侧栏。
- 高亮状态和当前导航使用亮黄绿色。
- 信息卡片使用浅奶油色、细边框和克制阴影。
- 日志和诊断结果使用深色面板，形成“诊断输出”的识别感。
- 布局保持紧凑，不使用营销页式大标题和大留白。

## 导航结构

第一阶段导航保持简单：

- `总览`
- `连接`
- `诊断`
- `设置`

侧栏始终显示。导航项使用图标加文字；图标优先从 `lucide-react` 选择。当前页面用亮黄绿色高亮。

应用启动后直接进入 `总览`，不做落地页或欢迎页。

## 总览页

`总览` 是默认首页，优先回答“现在运行时是否正常”。

核心内容：

- 页面标题：`运行时工作台`
- 副标题：`本机 QQ WS 诊断与连接状态`
- 全局状态徽标：
  - `空闲`
  - `正在监听`
  - `握手中`
  - `已就绪`
  - `已断开`
  - `错误`
- 顶部三张状态卡：
  - `运行目标`：通常显示 `QQ WS`
  - `握手状态`：显示 `等待中`、`已完成` 等中文状态
  - `最近诊断`：显示 `暂无`、`成功`、`失败`，必要时显示最近方法名
- 最近事件面板：
  - 展示最近运行时事件和日志摘要。
  - 使用深色面板样式，呼应诊断输出。
  - 首页只展示可快速扫描的信息，不展开完整日志细节。

当前实例、Host 版本、最后在线时间、最近错误可以作为次级信息展示。只有在已连接或出错时，才需要提高它们的视觉优先级。

## 连接页

`连接` 用于说明 QQ host 如何接入本机 WS 端点。

核心内容：

- WebSocket 地址和复制按钮。
- 期望 Host 版本。
- Token 预览，只显示部分内容，不展示完整 token。
- 当前连接状态。
- 下一步接入提示。

说明文字使用中文。URL、路径、token 预览等技术值使用等宽字体展示。

## 诊断页

`诊断` 是手动探测和查看结构化结果的工作区。

核心内容：

- 方法选择：`host.describe`、`gameCtl.probe`
- JSON 参数编辑区。
- 带 `Play` 图标的执行按钮，按钮文案使用 `执行`。
- 结果输出面板。
- 非法 JSON 的内联校验提示。
- 对未连接、不支持的方法、调用超时、运行时失败给出清晰中文错误。

诊断结果使用深色代码面板，因为它承载结构化调试数据。页面其他区域继续保持精致桌面工具风格。

## 设置页

`设置` 在第一阶段保持克制，不做超出后端能力的复杂配置中心。

核心内容：

- 监听地址。
- 监听端口。
- QQ WS 路径。
- 期望 Host 版本。
- 主题设置，如果第一阶段实现。
- 后端支持后再加入 token 重置操作。

危险操作，例如重置 token，后续实现时必须有明确确认。第一阶段如果后端尚未支持，就不在 UI 中伪造可点击能力。

## 文案规则

以下内容使用中文：

- 导航。
- 页面标题。
- 卡片标签。
- 状态标签。
- 空状态。
- 错误提示。
- 按钮文案。

以下内容保留原文：

- `Farm_Go`
- `QQ WS`
- `host.describe`
- `gameCtl.probe`
- WebSocket URL。
- JSON key。
- 原始诊断结果中的字段名。

最终 UI 不使用 `Runtime desk` 这类装饰性英文标题。确认的首页标题是 `运行时工作台`。

## 组件建议

沿用第一阶段计划中的 React、Tailwind CSS、shadcn-style 组件风格和 `lucide-react`。

建议组件：

- `AppShell`：常驻侧栏和主内容框架。
- `StatusBadge`：把运行时 phase 映射为中文标签和视觉状态。
- `MetricCard`：顶部紧凑状态卡。
- `LogViewer`：深色事件和诊断输出面板。
- `OverviewView`、`ConnectionView`、`DiagnosticsView`、`SettingsView`：页面级视图。

卡片应保持紧凑，圆角约 8 到 10px。避免卡片套卡片。页面分区使用正常布局，不做浮动装饰卡片。

## 数据流

UI 通过 Wails 绑定消费 Go 后端能力：

- `RuntimeStatus()`：驱动总览页状态徽标和状态卡。
- `ConnectionInfo()`：驱动连接页。
- `RunDiagnostic(method, params)`：驱动诊断页。

第一阶段可以先使用初始拉取和手动刷新。实时事件订阅等后端通过 Wails 暴露事件流后再加入。

## 错误处理

错误要清楚，但不应过度吓人。

- JSON 不合法：在编辑区附近显示 `参数不是合法 JSON`。
- 运行时未连接：结果面板或状态卡显示 `运行时未连接`。
- 协议错误或超时：包含方法名和简短中文解释。
- 首页最近错误：只展示最新且有用的一条，详细内容留给日志或诊断结果。

任何页面都不能展示完整 token、密码、session 或类似敏感值。

## 可用性要求

- 侧栏、卡片、徽标、深色面板都要保持足够对比度。
- 按钮尺寸稳定，有明确 hover 和 focus 状态。
- 图标只作为辅助信号，文字标签必须可见。
- 第一阶段计划中的最小窗口是 `960x640`，布局在该尺寸下不能溢出。
- 字号不随视口宽度缩放。

## 不在范围内

本设计不包含：

- 浏览器 WebUI。
- 营销页或欢迎页。
- 真实农场任务控制。
- WMPF、Frida、CDP 或自动化任务仪表盘。
- 复杂插件系统或调度系统 UI。

## 对第一阶段计划的实现备注

当前第一阶段计划里的 UI 示例偏绿色运维控制台。正式实现时应按本设计调整：

- 英文展示标题改为中文。
- 保留已确认的深色侧栏、温暖主画布和亮黄绿色强调。
- `总览` 保持状态优先。
- 可执行诊断放在 `诊断` 页，不作为启动首页。
