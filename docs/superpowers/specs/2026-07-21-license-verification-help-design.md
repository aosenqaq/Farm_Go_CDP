# 卡密验证失败帮助与连接诊断设计

## 目标

在卡密授权验证页面提供始终可见的“无法验证？”入口。用户可在帮助弹窗中查看常见排查建议，并使用本机网络对 `api.kauth.cn` 执行连接诊断。诊断比较系统 DNS、阿里公共 DNS、114DNS 和腾讯 DNSPod 的解析与 ping 结果，给出推荐项，但绝不修改系统 DNS 或网卡配置。

## 用户界面

### 授权页入口

“无法验证？”使用带帮助图标的次要文字按钮，固定放在现有授权反馈行右侧。反馈文案占据左侧可伸缩区域并允许换行，帮助按钮保持可点击且不被长错误文案挤出容器。没有反馈文案时仍保留该行高度和按钮位置，避免布局跳动。

点击入口打开固定遮罩弹窗。弹窗遵循现有 `dialog-backdrop`、浅色表面、8px 圆角和图标关闭按钮样式；支持关闭按钮、点击遮罩和 Escape 关闭。

### 帮助内容

弹窗标题为“无法验证？”，正文依次展示：

1. **检查卡密是否正确。** 请直接复制完整卡密，并检查首尾或中间是否包含空白符号。
2. **检查本机时区与时间。** 建议手动校准一次本地时间。
3. **检查验证服务器连通状态。** 可点击下方按钮检测本机到 `api.kauth.cn` 的连接。
4. **比较公共 DNS。** 检测会给出建议，但不会修改电脑的 DNS 设置。

正文下方按钮固定命名为“检查连接状态”。检测中按钮禁用并显示加载图标和“正在检查”；检测结束后恢复原名称，允许重新检查。

### 检测结果

首次打开弹窗时不自动检测。用户点击按钮后，结果区域显示：

- DNS 名称与地址；系统 DNS 显示“系统 DNS”，不虚构服务器地址。
- 解析出的首个 IPv4 地址。
- DNS 解析耗时。
- ping 成功次数与平均延迟。
- 单项失败原因。

候选项固定为：

| 名称 | 地址 |
| --- | --- |
| 系统 DNS | 使用操作系统当前配置 |
| 阿里公共 DNS | `223.5.5.5` |
| 114DNS | `114.114.114.114` |
| 腾讯 DNSPod | `119.29.29.29` |

有可连通项时，在表格上方突出推荐名称、DNS 地址和平均延迟，并显示“检测结果仅供本次网络诊断参考，不会自动更改系统配置”。全部失败时不推荐任何 DNS，改为提示用户检查网络、防火墙或联系服务提供方。

## 后端架构

在 Go/Wails `App` 上新增无需授权即可调用的只读诊断方法 `CheckLicenseConnection()`。授权页面本身处于未授权状态，因此该方法不能经过 `requireAuthorized`。方法只接受后端固定的域名与 DNS 候选列表，不接收前端命令、域名或 IP 参数，避免命令注入和诊断范围扩张。

后端将 DNS 查询、ping 命令执行和推荐排序拆成可独立测试的内部单元：

- 系统 DNS 使用 Go 默认解析器查询 `api.kauth.cn` 的 IPv4。
- 公共 DNS 使用带固定 UDP 53 目标的 Go 自定义解析器查询同一域名。
- 每组记录解析耗时，并选择该解析器返回的首个 IPv4 进行 ping。
- Windows 通过本机系统命令执行 `ping -4 -n 4 -w 1000 <IP>`。命令参数中的 IP 只能来自 `net.ParseIP` 验证后的解析结果。
- 四组检测并发执行，并受统一的短超时控制，防止授权帮助弹窗长时间等待。

本功能面向当前 Windows Wails 桌面产品。若系统 ping 命令不可用，返回明确的“不支持本机 ping 检测”状态，不用 HTTPS 请求伪装成 ICMP ping。

## Ping 解析与推荐规则

解析器逐行读取系统 ping 输出，只从包含 `TTL=` 的响应行提取 `time=数字ms`、`time<1ms`、`时间=数字ms` 或 `时间<1ms`。不读取本地化的汇总行，因此不依赖中文或英文的“平均”字段。`<1ms` 按 1 ms 计入整数平均值。

推荐排序规则固定为：

1. 只考虑 DNS 解析成功且至少收到一次 ping 响应的候选项。
2. 平均 ping 延迟更低者优先。
3. 平均 ping 相同时，DNS 解析耗时更低者优先。
4. 仍相同时，保持候选列表原始顺序，优先系统 DNS，减少不必要的配置建议。

DNS 解析耗时和 ping 平均延迟分别展示，不相加为一个缺乏实际含义的“综合延迟”。

## 数据流与状态

`App` 将 `CheckLicenseConnection` 作为回调传给 `LicenseGate`，保持组件测试不依赖真实 Wails 环境。弹窗维护关闭、检测中、报告和调用错误四类状态。

一次用户操作只允许一个在途检测。重复点击被禁用；关闭弹窗不取消后端命令，但迟到结果不得导致 React 警告，重新打开后可查看本次组件生命周期内的最近结果。重新点击检查会清除旧调用错误，并在新结果返回后原子替换报告。

后端返回结构化报告，不把原始命令输出传到前端。报告包含目标域名、检测时间、候选结果、推荐候选标识和整体错误文案。任何单项失败都留在对应候选结果中，不阻止其他结果返回。

## 错误处理

- DNS 未返回 IPv4：该项显示“未解析到 IPv4 地址”。
- DNS 查询失败或超时：该项显示“DNS 解析失败”或“DNS 解析超时”。
- ping 部分丢包：使用成功响应计算平均值，同时显示成功次数，例如 `3/4`。
- ping 全部超时：该项显示“连接超时”，不参与推荐。
- ping 命令启动失败：该项显示“本机 ping 不可用”，不展示原始系统错误或路径。
- 整体调用失败：弹窗保留帮助内容和重试按钮，在结果区域显示通用错误。

所有错误文案不得包含卡密、SDK token、完整命令输出或本机敏感路径。

## 测试与验证

### Go 测试

- 中文与英文 Windows ping 成功输出均可提取四次延迟并计算平均值。
- `<1ms`、部分丢包、全部超时和无效输出得到正确结构化结果。
- DNS 失败不阻断其他候选项。
- 推荐规则覆盖平均 ping、解析耗时和稳定顺序三层排序。
- 固定域名、固定 DNS 列表与 IP 验证确保前端不能注入命令参数。
- 并发检测受整体超时约束。

### React 测试

- “无法验证？”始终位于反馈行并可打开弹窗。
- 弹窗包含四条排查建议与准确的 DNS 名称、地址。
- 关闭按钮、遮罩和 Escape 可关闭弹窗。
- 检测中按钮禁用并显示加载状态。
- 成功、部分失败、全部失败和调用拒绝分别渲染正确结果。
- 长授权错误文案不隐藏或挤出帮助入口。

### 完整验证

运行完整 Go 测试、前端 Vitest 和前端生产构建。随后启动 Wails 开发环境，在实际授权页验证弹窗层级、窄窗口布局、重复检查和本机真实检测结果。

## 非目标

- 不自动或手动代替用户修改系统 DNS。
- 不请求管理员权限。
- 不改变卡密登录、记住卡密或授权生命周期行为。
- 不将 HTTPS 请求延迟描述为 ping 延迟。
- 不新增可输入任意域名、IP 或 DNS 的通用网络工具。
