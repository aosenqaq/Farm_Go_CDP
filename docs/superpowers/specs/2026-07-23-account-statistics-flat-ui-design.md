# 账户运行统计扁平 UI 设计

**日期：** 2026-07-23  
**范围：** 账户状态页的运行统计弹窗

## 目标

- 将弹窗内现有 8 个大尺寸统计卡片改为与工作台一致的扁平统计项。
- 保持日期范围筛选、弹窗尺寸、关闭交互和统计计算不变。
- 将原“覆盖天数”替换为随当前日期范围聚合的“预估收益”。
- 桌面端与局域网移动端同时更新。
- 不影响账户资产、肥料容器等继续使用通用 `Metric` 的区域。

## 组件设计

在 `AccountStatusView` 内新增弹窗专用的 `AccountStatistic` 小组件，不抽取跨页面公共组件，也不修改通用 `Metric`。每项由彩色 Lucide 图标、指标名称和右对齐数值组成，并使用专用类名与账户页其他卡片隔离。

现有 8 项数据和含义保持不变：

| 指标 | 图标语义 | 颜色方向 |
| --- | --- | --- |
| 运行次数 | 活动/运行 | 紫色 |
| 收获 | 植株 | 绿色 |
| 务农 | 农机 | 青绿色 |
| 偷菜 | 菜篮 | 橙色 |
| 好友帮忙 | 援助 | 蓝色 |
| 好友捣乱 | 干扰 | 红色 |
| 出售 | 金币 | 金黄色 |
| 预估收益 | 金币收益 | 紫蓝色 |

图标仅用于快速识别，名称和数值继续作为完整文本输出。缺失计数仍沿用当前格式化结果。预估收益按照当前筛选范围汇总：今天显示今天，近三天汇总最近三天，近七、十五、三十天同理；数据未完整准备时显示 `-`。

## 布局与视觉

- 桌面端统计区为 4 列 2 行。
- 640px 以下为 2 列 4 行。
- 统计项采用浅灰白背景、无边框、无阴影、6px 圆角和紧凑内边距。
- 图标固定尺寸，名称允许在极窄空间省略，数值保持右对齐并不得覆盖相邻内容。
- 日期范围按钮、弹窗背景、标题、关闭按钮和滚动规则维持现状。

## 数据流

仓库出售记录是预估收益的唯一数据源。存储层新增按账户和日期范围聚合 `total_amount` 的查询，一次返回各日期收益，避免账户刷新时逐日查询。查询必须使用账户键和起止日期作为结构化参数，并按日期分组。

Go `DayStats` 增加 `saleEstimate` 与 `estimateReady`。账户状态构建近 30 天自动化统计后，补齐范围内的每个日历日期，再将出售收益合并到对应日期；没有自动化事件或出售记录的日期计数与收益均为 `0` 且收益已就绪。聚合查询失败时，该窗口内每日收益均标记为未就绪。现有 `sell` 字段继续表示出售任务次数，不改变含义。

前端 `DayStatsLike`、标准化和窗口求和加入这两个字段。`buildStatsWindow` 对所选日期集合累加 `saleEstimate`，只有所有选中日期均已就绪时才返回可显示收益。`AccountStatisticsDialog` 把原“覆盖天数”替换为“预估收益”，并继续保留第 7 项“出售”次数。

账户状态页面仍使用原有一次请求，不额外调用工作台统计接口，也不改变日期范围状态和弹窗交互。

## 测试与验收

1. 存储测试确认收益按账户和日期范围隔离并按天求和。
2. Go 账户状态测试确认每日收益写入历史，查询失败时不返回误导性金额。
3. 前端窗口测试确认今天、近三天和其他范围按选中日期正确汇总收益，任一日期未就绪时显示 `-`。
4. 组件测试打开统计弹窗后确认渲染 8 个专用扁平项及对应图标，不再渲染弹窗内的 `.metric-card`。
5. 样式测试确认桌面 4 列、移动端 2 列，统计项无边框无阴影，数值右对齐。
6. 现有弹窗打开、日期范围和关闭交互测试继续通过。
7. 运行相关 Go 测试、账户状态聚焦测试、完整前端测试和生产构建。
8. 确认 `frontend/dist/index.html` 引用新生成的哈希资源。

## 非目标

- 不修改现有任务次数字段、时间范围或计算方式。
- 不重做弹窗或日期筛选器。
- 不改变账户页其他指标卡片。
- 不把出售任务次数当作出售收益，也不新增前端轮询请求。
