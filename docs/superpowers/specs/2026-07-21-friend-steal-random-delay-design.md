# 好友偷菜随机延迟设计

## 目标

为自动好友偷菜增加可选的随机延迟。默认关闭；启用后，每轮发现至少一个符合条件的偷菜好友时，先随机等待一次，再并发发起该轮所有好友的协议操作。

## 范围

- 仅影响自动化任务 `friend_steal`。
- 延迟范围由用户以毫秒配置，默认最小值 `1000`、最大值 `5000`。
- 同一轮只抽取一次随机值。该值由整批候选好友共享，不会对每个好友或每块土地追加等待。
- 关闭开关时保留现有的即时并发行为。

不改变好友偷菜的调度轮次间隔、好友筛选规则、作物名单规则、黑名单冷却、并发数或协议回包等待时间。

## 配置契约

在自动化配置中新增以下键：

| 配置键 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `autoFarmFriendStealRandomDelayEnabled` | bool | `false` | 是否在每轮好友偷菜前启用随机等待 |
| `autoFarmFriendStealRandomDelayMinMs` | int | `1000` | 随机等待下限，单位毫秒 |
| `autoFarmFriendStealRandomDelayMaxMs` | int | `5000` | 随机等待上限，单位毫秒 |

范围使用闭区间 `[min, max]`。最小值和最大值必须是非负整数，且 `max >= min`。后端在读取配置时也执行同样的防御性归一化，避免旧数据、导入数据或直接 API 调用绕过界面校验。

## 执行流程

1. 读取好友列表，应用现有的可偷状态、好友规则、黑名单冷却及好友上限筛选。
2. 没有候选好友时立即返回，绝不等待。
3. 开关关闭时直接调用现有候选好友并发执行逻辑。
4. 开关开启时，从配置闭区间抽取一个毫秒值，并以可取消等待方式等待一次。
5. 等待完成后，调用现有 `runFriendStealCandidates`。其现有并发池保持不变，因此同一批好友会在等待后并发进入好友农场并发起偷取协议。
6. 任务上下文在等待期间取消时，立即结束任务且不再发起好友农场或偷取协议。

随机等待放在候选好友筛选之后、`runFriendStealCandidates` 之前。这样不会为无目标轮次付出等待时间，也不会把延迟分散到各个并发工作协程中。

## 界面

控件位于现有“好友偷菜”设置区，紧接当前“偷菜间隔(秒)”一行：

```text
[✓] 好友偷菜       偷菜间隔(秒) [ 90 ]     黑名单跳过冷却(分钟) [ 10 ]

[ ] 随机偷取延迟   最小延迟(ms) [1000]     最大延迟(ms) [5000]
```

- 开关默认未选中。
- 开关关闭时，两个范围输入显示已保存数值但为禁用状态。
- 开关开启时，两个范围输入可编辑。
- 保存时若输入不是非负整数或最大值小于最小值，显示明确错误并不提交该次配置。

## 测试

- 后端默认配置包含开关关闭及 `1000` 至 `5000` 的范围。
- 关闭开关时，候选好友立即进入现有并发流程。
- 开关开启时，筛选出候选好友后只调用一次延迟选择和等待，再启动整批并发处理。
- 无候选好友和等待期间被取消时，不发起好友农场或偷取协议。
- 随机值在边界范围内，且非法范围得到防御性处理。
- 前端渲染随机延迟开关及范围输入；关闭时禁用范围输入；非法范围阻止保存。
