# 账户状态运行头像与身份顶栏设计

**日期：** 2026-07-23
**范围：** 桌面端与 LAN 移动端账户状态页

## 目标

- 在账户状态页显示当前游戏运行时返回的真实账户头像。
- 采用已确认的 B 方案，将账户身份与经验进度分层展示。
- 提升昵称、GID、等级、经验和资产的扫描效率，同时保持现有页面风格。
- 桌面端与 LAN 移动端使用相同的数据和组件语义，仅通过响应式样式调整密度。

## 现状与约束

Go `AccountProfile` 已包含 `avatarUrl`，`BuildRuntimeAccountProfile` 也已从运行时资料读取该字段。LAN RPC 返回值会将外部 `avatarUrl` 改写成受当前认证会话保护的 `/farm-avatars/<token>` 同源地址，因此本次不新增头像协议、代理路由或后端请求。

前端 `AccountStatusView` 的本地 `AccountProfileLike` 尚未声明 `avatarUrl`，账户资产区域也没有消费头像字段。现有 `FallbackImage` 已用于侧栏和账户确认弹窗，原始图片失败时会改用 `/logo.png`。

## 已选布局

账户资产区域按以下顺序排列：

1. 区域标题与资料读取状态。
2. 账户身份顶栏。
3. 经验升级进度。
4. 金币、金豆豆、点券和钻石。

身份顶栏采用浅绿色平面背景，不增加独立边框或阴影。它不是新的嵌套卡片，只用于分组当前账户身份。经验区继续使用现有浅色成长背景和左侧亮绿色强调线，但不再重复昵称与等级。

### 桌面端

- 身份顶栏使用 52px 圆形头像。
- 头像右侧显示昵称，下一行显示 `GID <number>`。
- 等级作为独立的 `Lv. <number>` 标签置于顶栏右侧。
- 经验进度独占下一行，保留当前值、目标值、下一等级和剩余经验。
- 四项资产保持一行四列，账户资产区整体高度预计增加约 40px。

### LAN 移动端

- 仅在 `.app-shell-remote` 且视口不超过 760px 时启用移动规则。
- 信息顺序与桌面端一致，头像缩为 44px。
- 昵称和 GID 占据中间弹性列，等级固定在右侧，不与长昵称争抢宽度。
- 经验进度独占身份顶栏下方一行。
- 四项资产使用两列两行，避免数值在窄屏截断或相互覆盖。
- 页面继续使用主滚动区，不新增横向滚动或局部嵌套滚动。

肥料容器、活动货币、运行统计、页面导航和桌面端账户侧栏维持现状。

## 组件边界

在 `AccountStatusView.tsx` 内新增私有 `AccountIdentityBar`，输入完整的 `profile`，仅负责以下展示：

- `profile.avatarUrl`
- `profile.name || profile.nick || '-'`
- `profile.gid`
- `profile.level`

现有 `AccountGrowthCard` 收敛为纯经验进度组件，并使用与职责一致的本地名称。两个组件都保留在账户页面文件内，不抽取新的跨页面公共身份组件，也不修改侧栏和账户确认弹窗。

`AccountProfileLike` 增加可选的 `avatarUrl?: string`。`gid`、昵称和等级继续使用现有字段，不增加第二份账户状态或额外属性传递。

## 数据流

```text
游戏运行时资料
  -> FarmAccountStatus
  -> AccountStatusPayload.profile.avatarUrl
  -> 桌面端直接使用运行时 HTTPS 地址
  -> LAN 端 RPC 自动改写为 /farm-avatars/<token>
  -> AccountIdentityBar
  -> FallbackImage
```

初次加载和手动刷新继续走现有 `loadAccountStatus` 与 `applyPayload`。头像、昵称、GID、等级和经验随同一个资料对象原子更新，不单独轮询。头像渲染实例按 `avatarUrl` 标识；刷新得到新地址后必须重新尝试加载，不能保留上一地址的失败状态。

## 加载与异常状态

- 资料尚未返回：固定尺寸头像容器继续占位，内部显示 `UserRound`，页面现有“正在读取账户资料...”文本负责表达加载状态。
- `avatarUrl` 为空：显示 `UserRound`，不渲染空 `img`。
- 头像正常：使用运行时头像，并以当前昵称作为替代文本。
- 图片请求失败：沿用 `FallbackImage`，切换到 `/logo.png`。
- GID、昵称或等级缺失：对应文本显示 `-`，不得导致身份顶栏塌陷。
- 账户资料整体失败：保留当前页面错误文本和空数据展示，不增加重复提示。

头像只用于身份识别，不可点击，不提供查看大图、上传或编辑入口。

## 视觉与可访问性

- 头像容器始终声明宽高并使用圆形裁切，避免图片加载造成布局偏移。
- 图片使用昵称作为 `alt`；图标兜底保持非交互语义。
- 昵称允许单行省略，GID 和等级使用稳定数字展示，不得覆盖相邻内容。
- 普通文字与背景保持不低于现有页面对比度，状态含义不只依赖颜色。
- 本次不增加动画；现有经验条宽度过渡保持不变。

## 测试与验收

1. 账户页渲染测试传入 `avatarUrl`、昵称、GID 和等级，确认身份顶栏输出正确图片地址、替代文本和身份信息。
2. 未提供 `avatarUrl` 时确认渲染 `UserRound`，且不产生空图片地址。
3. 头像地址变化时确认新图片能够重新加载，不沿用旧地址的失败状态。
4. 保留现有经验值、下一等级、剩余经验和四项资产格式化断言。
5. 样式检查确认桌面端 52px 头像与四列资产，LAN 移动端 44px 头像与两列资产。
6. 在 375px 移动视口检查长昵称、GID、等级和最大长度资产值不溢出、不重叠。
7. 在桌面视口确认账户资产区与肥料、活动货币区对齐，页面主滚动正常。
8. 运行账户状态页聚焦测试、完整前端测试和 `npm run build`。
9. 后端不改动，但现有账户状态测试与 LAN 头像代理测试必须继续通过。

## 非目标

- 不新增或修改游戏运行时协议。
- 不修改 LAN 头像代理的安全边界、缓存策略或会话绑定。
- 不改造侧栏账户面板和账户确认弹窗。
- 不重新设计肥料容器、活动货币或运行统计。
- 不增加头像交互、账号切换或账户编辑能力。
