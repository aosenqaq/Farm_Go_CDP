# 应用推荐配置设计

## 目标

允许用户在自动化页明确确认后，将应用作者当前设备上已验证的推荐配置应用到当前账号；只覆盖农场自动化区域和仓库自动出售配置，随后提醒用户检查并按需调整。

## 推荐配置来源

推荐配置是应用作者当前设备上运行的已验证配置快照，不是点击按钮的用户当前配置。后端维护这份快照，作为唯一推荐来源；前端不保存或拼装推荐值。

## 覆盖范围

后端通过字段白名单将推荐快照覆盖到当前账号已有的配置中。

- 覆盖农场自动化区域的全部已支持配置字段，包括自动化任务开关、执行间隔与相关农场配置。
- 覆盖仓库自动出售的开关、出售间隔和出售分类。
- 不覆盖账号、好友、消息推送及任何未列出的配置。
- 推荐值保存后仍须走现有账号隔离、规范化和调度器重配置流程，确保仓库自动出售与调度中心保持同一份实际配置。

## 前端交互

自动化页保留“应用推荐配置”入口。点击后显示二级确认弹窗：

- 标题为“应用推荐配置”。
- 明确列出将覆盖“农场自动化”和“仓库自动出售”。
- 明确列出账号、好友、消息推送及其他未列出的配置不会被覆盖。
- “取消”和关闭按钮不产生写入。
- “确认应用”在请求期间禁用，防止重复提交。

成功时关闭确认弹窗、以接口返回的最新状态刷新自动化页，并显示：

> 推荐配置已应用，请检查各项配置是否生效，并可根据自身需求进行调节。

失败时保留确认弹窗，恢复按钮可用状态，并显示后端返回的错误信息。

## 后端接口与保存语义

新增一个应用推荐配置接口。调用时使用当前已解析的账号作用域读取目标配置，基于现有完整设置生成更新结果，并只修改白名单字段。接口调用现有持久化入口保存农场自动化与仓库自动出售配置，返回保存后重新加载的自动化状态。

应用必须具有原子性：读取、生成和校验推荐更新可以在内存完成；若任一持久化步骤失败，接口返回错误且不返回成功状态，不能让前端显示配置已应用。仓库自动出售保存失败时，不应用新的调度配置。

## 测试

- 后端：推荐应用会更新农场自动化白名单字段和仓库自动出售字段。
- 后端：账号、好友、消息推送及白名单之外字段保持原值。
- 后端：应用结果按当前账号隔离，且仓库自动出售会沿用现有调度器重配置路径。
- 后端：任一保存失败时返回错误，不报告成功或刷新为已应用状态。
- 前端：入口可打开确认弹窗，取消和关闭不会调用应用接口。
- 前端：确认会调用接口并在提交期间防重复点击；成功显示指定提示并使用返回状态刷新；失败保留弹窗和错误信息。
- 前端：确认弹窗清晰显示覆盖和不覆盖范围。

## 非目标

- 不提供用户自定义推荐模板、导入导出或选择性勾选字段。
- 不改变现有配置页面、运行时协议或自动化任务执行行为。
