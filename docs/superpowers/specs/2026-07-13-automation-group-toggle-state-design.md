# 自动化功能组总开关状态保留设计

## 目标

农场自动化中，关闭任一功能组的总开关时，只暂停该组的执行入口；详情页内各子功能当前的启用状态必须保留。重新打开总开关后，子功能恢复到关闭前的状态。

## 当前行为

前端 `AutomationView` 的功能组切换已不再直接修改子功能，但后端 `StateFromSettings` 仍会在功能组关闭时将关联任务计算为不可执行，并把这个有效运行状态回写到子功能配置键。这会将用户已启用的子功能持久化为关闭，导致重新打开功能组后无法恢复原配置。

## 设计

### 状态模型

- 每个功能组使用独立的 `autoFarmFeatureGroupEnabled.<groupId>` 配置键，表示该功能组是否允许执行；这避免与“自动施肥”“神秘商店自动购买”等子功能共用同一个键。
- 子功能继续使用各自的配置键与持久化任务 `enabled` 字段，表示个人启用偏好。
- `StateFromSettings` 仅将父开关用于计算调度器看到的有效任务状态。父开关造成的有效关闭不得写回子功能配置键或持久化任务偏好。
- 两种状态独立保存。重新开启父开关时，调度器从保留的子功能偏好重新计算有效任务状态。

### 交互

- 功能组关闭时，详情页保留子功能的勾选和输入值，但其开关、字段、选择器以及手动执行操作均不可操作；调度器不会选择该组任务。
- 功能组重新开启时，详情页控件恢复可操作；所有子功能显示并使用关闭前保存的状态。
- 调度中心中的子任务开关仍代表子功能自身状态，不由功能组总开关改写。

### 持久化和兼容性

- 沿用现有 API 状态结构；仅在现有 `config` 映射中写入功能组专用键，不新增传输字段。
- 读取旧配置时，缺少新功能组键的记录继续按旧功能组键或子任务启用状态推断一次；下一次保存时写入新键。
- 已被旧版本关闭时清空的子功能无法推断原值，保持现有关闭状态；本次修复只防止后续切换继续清空。

## 测试

- 功能组开关关闭后，保存的子功能配置键和任务偏好保持原值，调度器任务只在返回状态中显示为有效关闭。
- 关闭后再打开功能组，关联子任务和子功能配置键保持原值，并恢复为有效启用。
- 同一设置在调度器运行中重新配置时，父开关关闭不会执行子任务，重新开启后会按照原有子功能偏好恢复。
- 详情页在功能组关闭时禁用组内可编辑控件和手动操作，重新开启后恢复。

## 非目标

- 不恢复已经被旧行为持久化为关闭的历史子功能配置。
