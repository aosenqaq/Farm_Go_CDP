# 自动化好友黑白名单执行设计

## 目标

让自动好友偷菜、帮助和捣乱与手动好友操作使用相同的账户级黑白名单语义。当前名单匹配、作用范围和低等级屏蔽已在社交模块生效；本次将其应用到自动化候选人筛选，不改变前端配置或游戏协议。

## 范围

本次只调整以下模块：

- 社交模块中可复用的好友规则匹配与候选人过滤逻辑。
- 自动化运行时的社交规则读取能力。
- 自动偷菜、自动帮助和自动捣乱的候选筛选顺序。
- 对应的自动化回归测试。

不改变名单数据格式、规则界面、协议调用参数、自动帮助最大并发或偷菜作物黑名单策略。

## 规则语义

规则继续按当前账户读取并标准化。对于指定操作范围：

1. 黑名单开关启用且范围命中时，名单命中好友被排除。
2. 低等级屏蔽在黑名单生效的范围内同样排除好友。
3. 白名单开关启用且范围命中时，只保留名单命中好友。
4. 黑名单优先于白名单；同一好友同时命中时仍排除。
5. 规则范围未启用时，不因该名单筛选好友。

名单仍可按 GID、显示名称、名称和备注匹配，与手动操作完全一致。

## 架构

在 `social` 包中提供纯候选人过滤入口，接收原始好友候选、`FriendRules` 和操作范围，返回允许执行的候选。手动操作的规则判定也复用相同的底层决策，以防止两条路径再次产生差异。

自动化运行时增加只读好友规则接口。正式应用通过既有 `socialStorageAdapter` 提供该接口，并按任务启动时的账户键读取规则。没有社交存储的离线构造使用默认空规则，保持现有基础运行时测试的行为；正式应用读取规则失败时任务失败并不得继续发起好友协议。

## 候选顺序

自动偷菜：

1. 读取当前好友并筛选可偷候选。
2. 排除作物黑名单冷却中的好友。
3. 应用 `steal` 范围的好友规则。
4. 应用最大好友数。
5. 执行现有作物规则与偷菜协议。

自动帮助：

1. 读取当前好友并筛选可帮忙候选。
2. 开启“仅帮助护主犬好友”时，与当前账户护主犬缓存求交集。
3. 应用 `help` 范围的好友规则。
4. 应用最大好友数。
5. 执行现有并发帮助协议。

因此，命中帮助黑名单的护主犬好友会在限制人数前被移除，不会被帮助，也不会占用帮助名额。

自动捣乱：

1. 读取当前好友并筛选可捣乱候选。
2. 应用 `mischief` 范围的好友规则。
3. 应用既有日限额和候选限制。
4. 执行现有捣乱协议。

## 结果与异常

规则过滤后的候选为空时，各任务沿用现有“本轮跳过”成功结果，不发起好友农场检查或动作协议。规则读取失败返回明确失败结果。护主犬缓存读取失败仍保持失败，不回退到全体好友。

## 测试

新增自动化回归测试，至少覆盖：

- 三个自动任务分别排除其范围内的黑名单好友。
- 三个自动任务分别只执行其范围内白名单好友。
- 低等级屏蔽在启用的范围内排除好友。
- 自动帮助同时启用护主犬模式和帮助黑名单时，不检查或帮助被拉黑护主犬，且其不占用最大好友数。
- 规则读取失败时不调用任何好友检查或动作协议。

保留现有手动规则测试，并验证全量相关 Go 包测试通过。
